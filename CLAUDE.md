## Product summary

A **live, time-boxed shared shopping basket** for families and housemates.

- The shopper opens a basket with one tap and sets a duration (e.g. "checkout in 8 minutes").
- Everyone in the household gets a push notification and can add items.
- Added items appear instantly on every device (Serverpod streaming).
- When time runs out, the basket closes **on the server** (future call). Works even if the app is killed or the phone dies.
- **Only the shopper** can extend the timer.
- At checkout the basket freezes, the shopper enters prices, and the **server** calculates who owes whom.
- The only thing shared is the remaining time. **Live location is never sent to or stored on the server.**

## Tech stack

- Backend: Serverpod (Dart), PostgreSQL, Redis (optional, for multiple instances)
- Client: Flutter (Android first, iOS second)
- State: Riverpod
- Auth: Serverpod auth module (email sign-in)
- Push: Firebase Cloud Messaging (HTTP v1 API, sent from the server)
- Localization: `flutter gen-l10n` with `app_en.arb` as the only language for now
- Deploy: Serverpod Cloud or Docker on a VPS

> Serverpod API names change between versions (especially the auth module and the future call API). Before writing code, check the official docs for the version installed in this project. Do not guess.

1. **Contract first.** All `.spy.yaml` models and all endpoint signatures (bodies throwing `UnimplementedError`) land on `main` on Day 2, before parallel work starts. B then builds against a typed, compiling client instead of waiting for endpoints.
2. **`main` is protected.** Work on `feat/*` branches, open a PR.
3. **The other person's Claude reviews the PR** (`/code-review`). A fresh agent that did not write the code is worth more than the one that did. Reviews happen within 24h.
4. **A commit that finishes a task also ticks its checkbox in `PLAN.md`.** That file is the shared status board both agents read.
5. **Architecture decisions go into `docs/ARCHITECTURE.md`** as a short paragraph, the moment they are made.
6. **Start every session** by reading `PLAN.md` and the commits since yesterday.
7. **Days 8-10 (streaming) are pair work, not parallel work.** `basket_stream_endpoint` and `live_basket_controller` share event types, snapshot ordering and reconnect behaviour; splitting them costs more than it saves, and they sit on the critical path to the Day 10 deploy.

## Hard rules (Claude Code must follow these)

1. **The server is the source of time.** `closesAt` lives on the server. The client only displays `closesAt - serverNow`; server time is fetched on connect to correct clock drift.
2. **Auto-close must be idempotent.** When the future call fires it reloads the basket; if `status != open` or `closesAt > now` it does nothing. Extending the timer schedules a new future call; the old one simply becomes a no-op. On server startup, expired `open` baskets are swept and closed.
3. **Every endpoint checks authorization.** Non-members of a household get an error. Extend, freeze, price entry and settle are shopper-only.
4. **At most one open basket per household** (MVP rule, enforced in the DB inside a transaction).
5. **Money is stored as `int` in minor units** (cents / kuruş). No `double`. Currency is a household setting, formatted with `intl`.
6. **Settlement is computed on the server.** A `settled` basket and its `SettlementLine` rows are immutable.
7. **Location:** device location is read once, only on the shopper's phone, only to suggest an ETA. The server only receives the chosen store and a duration in minutes. Location is never logged.
8. **Every key event is written to `analytics_event`** (basket_opened, item_added, basket_extended, basket_frozen, basket_auto_closed, basket_settled, basket_cancelled).
9. Never edit `open_basket_client` or `*.g.dart` by hand. After model changes run `serverpod generate`; after schema changes run `serverpod create-migration`.
10. **Everything is in English:** UI, notifications, error messages, code, commits, docs. No hardcoded UI strings: every user-facing string goes through `app_en.arb` so another language can be added later without refactoring.

## Basket state machine

```
open ──(timer ends / shopper taps "At checkout")──> frozen ──(prices entered, settle)──> settled
  │
  └──(shopper cancels)──> cancelled
```

- `open`: anyone in the household can add items; the shopper can extend.
- `frozen`: no new items; the shopper marks items "Got it / Not available" and enters prices.
- `settled`: locked, read-only.

## Copy tone

Short, friendly, action-first. Examples:
- Notification: "Kaan is heading to Migros. Add what you need in the next 10 min."
- Reminder: "2 minutes left on the basket."
- Banner: "Checkout in 8:00"
- Settlement: "Ayşe owes Kaan ₺84.50"
